# UNDERSTANDING-SUMMARY — فهم الاتجاه المعتمد قبل التنفيذ

## 1. الفلسفة الحاكمة

- **Active Clarity (§4):** واجهة نشطة ومتزنة، مهنية دون برود، قريبة دون طفولية، تساعد صاحب مشروع أردني مستعجلًا على فهم وضعه واتخاذ الإجراء التالي بثقة مع بقائه يقظًا.
- **قاعدة القبول الحاكمة (§3):** يُرفض أي حل يشبه UI Kit عامًا أو Dashboard مولّدًا حتى لو كان نظيفًا تقنيًا. `Behavioral Familiarity Lock` (سلوك المنصة لا يُعاد اختراعه) مع `Micro Visual Expression` (الشكل والتكوين والهوية لا تُنسخ من قوالب).
- **التكوين (§5):** `Hierarchical Modular Layout` — وحدة رئيسية كبيرة تقود، وحدات متوسطة، بطاقات أفقية للثانوي، صفوف مفتوحة للمتكرر؛ لا شبكة بطاقات متساوية، ولا إخفاء أساسي في Carousel، والتمرير الأفقي يبدأ من اليمين ويكشف جزءًا من العنصر التالي.

## 2. الهوية البصرية (§§6–9)

- **Structured Soft Geometry:** هندسة لينة منضبطة؛ أنصاف أقطار: بطاقات رئيسية `20–24px`، متوسطة `14–18px`، أزرار `14–16px`، حقول `12–16px`. حدود وظيفية فقط، ظل خفيف عند ارتفاع حقيقي، صفوف مفتوحة للمتكرر، و`Pills` محصورة في حالات قصيرة محددة.
- **Light Mode فقط (§8):** Canvas `#F4F6FA`، سطح أبيض، Deep Ink `#171923` للنص، Electric Indigo `#4F46E5` أساسي (Pressed `#3F37C9`، Soft `#E8E7FF`)، Citrus Lime `#D9F43B` للمسات الحيوية (Deep Ink نصًا فوقه، ولا يُستخدم لتأكيد مالي)، Terracotta `#C45F46` مساند 5–8% دون قيادة أو نص صغير. توزيع إرشادي 70/20/10. ألوان دلالية معتمدة (نجاح `#137A55`، تحذير `#A65A00`، خطر `#C2354B`، معلومات `#1D64D8`، جزئي `#6E5AA8`، غير معروف `#697386`، محفوظ محليًا `#52657A`) مع أسطحها الخفيفة. أزواج Foreground/Background موثقة ويحظر التركيب العشوائي. `Border #D8DDE8` زخرفي و`Interactive Boundary #7A8292` للحدود الوظيفية فقط.
- **الطباعة والأرقام (§7 و§16.2):** Alexandria أساسي (Regular/SemiBold/Bold) وNoto Sans Arabic fallback، سلم وظيفي (Hero → Navigation)، أرقام إنجليزية `0–9` فقط مع منع الهندية، تنسيق `1,250.50 د.أ` (فاصلة آلاف وفاصلة عشرية نقطية)، عزل الأرقام LTR داخل RTL، Tabular Numbers للقيم، تاريخ `DD/MM/YYYY`، هاتف LTR.

## 3. النظام المالي (§13) — جوهر الصدق

- **Question-First (§13.2):** تُرتب الشاشة على أسئلة المستخدم: كم معي الآن؟ ماذا دخل وخرج؟ ما لي وما عليّ؟ هل أنا ربحان أم خسران؟ هل النتيجة مكتملة؟ — لا بطاقات متساوية، والسؤال الأهم يقود بكتلة قوية.
- **حالات القيمة (§13.20):** `0.00` للصفر الحقيقي فقط؛ `غير مسجل`؛ `لا يمكن حسابه`؛ `نتيجة تقديرية` مع Partial Signal؛ الغياب يظهر `—` مع تفسير ولا يتحول إلى صفر. محور الحفظ منفصل: `محفوظ على هذا الهاتف`، `لم يتم الإرسال`، `لم تُحفظ العملية`.
- **Snapshot Deck (§13.4):** بطاقة مالية كبيرة واحدة ظاهرة (Radius 24، Padding 20، قيمة 32–36 Bold)، Swipe مع مؤشر `1 من 4`، رأس قسم `نظرة مالية` يمينًا و`عرض الكل` يسارًا؛ الحالات العاجلة لا تُخفى في Swipe. ترتيب: الكاش، النتيجة، ديون لك، ديون عليك.
- **Impact Preview (§13.8):** قسم «أثر العملية» داخل النموذج فوق الإجراء النهائي، بصيغة قبل/بعد مثل `100.00 ← 115.00 د.أ`، قيم غير محسوبة تظهر `—` مع Partial Signal والسبب؛ القيم معناها من منطق المنتج — الأمثلة عرض تنسيق فقط.
- **النتيجة والاكتمال (§13.11):** مكتملة `ربح 420.00 د.أ` + «بحسب جميع البيانات المسجلة»؛ جزئية «نتيجة تقديرية» مع ذكر الناقص؛ متعذرة «النتيجة غير متاحة بعد» + `—`. البطاقة Indigo أو Deep Ink ولا تتحول للأخضر/الأحمر.
- **Charts (§13.13–13.15):** مشروطة بسؤال منتج وبيانات مناسبة؛ `FIN-CHARTS` جرد مشروط لا شاشة إلزامية — لن أرسم رسومًا في هذه الجولة وأوثّق الشرط.
- **Guidance Layer «الأهم الآن» (§13.19):** Insight واحدة قابلة للإجراء ببنية خلاصة → دليل → اكتمال بيانات → إجراء واحدة؛ لا تقولات ذكاء اصطناعي ولا Sparkles.

## 4. النظام السياقي (§14)

خمسة مستويات معنى (هادئ → مانع)؛ الحالات تحولات داخل المكون المضيف وفق `Anchor → Reveal → Recover` وثبات المكان. المكونات: `Micro Context Trace` (أثر نصي صغير)، `Micro Reveal Row` (توسع الصف)، `Micro Context Seam` (طبقة داخل القسم)، `Micro System Ribbon` (حالة عامة بالمنطقة العلوية مثل Offline)، `Micro Recovery Stage` (استبدال المنطقة المتعطلة فقط). خمسة أنواع Empty (First Move / Continuation / Search Reset / Period Gap / Clear State). التحميل `Content-Shaped` بمؤشر واحد متحرك؛ النجاح `Causal Feedback` بلا Toast لكل فعل؛ الخطأ `Preserve → Expose → Recover → Resolve` بلا Shake؛ Offline `Continuity Thread` يفصل الاتصال عن الحفظ عن الإرسال.

## 5. النماذج (§12) والتفاعل (§15) والوصول (§16)

- **Guided Open Forms:** نموذج سريع 3–5 مدخلات، Segmented لنقدي/آجل، حقل مبلغ بـ`د.أ` في الطرف المقابل وأرقام LTR، أخطاء محددة بعد محاولة المتابعة (لا أثناء أول كتابة)، إجراء نهائي باسم النتيجة (`تسجيل البيع`) ثابت فوق Safe Area، خروج بتغييرات يفتح Dialog بأفعال صريحة.
- **Micro Response Chain:** Discoverable → Acknowledge (50–100ms) → Commit → Resolve → Settle. حركة `Rooted Motion` بمصدر ووجهة، ضغط `Compression` بلا Ripple/Bounce، انتقال شاشة RTL `240–320ms`، Sheet `220–280ms`، Dialog `160–220ms`، والإغلاق أسرع بـ30–50ms. `One Active Motion Rule`. Reduced Motion يزيل الاتجاه وScale ويستبدلها بتغير محلي/Fade `100–150ms` دون فقدان المعنى.
- **الوصول وRTL (§16):** لمس `44×44px` (تنقل 48)، Focus Contour بسمك ~2px (Indigo على الفاتح، Citrus فوق Indigo)، أسماء قارئ شاشة عربية تُعلن الاسم/الدور/الحالة/القيمة، التمييز لا يعتمد على اللون وحده، دعم تكبير 200% وReflow من 320px مع ترتيب حماية (الرقم → الحالة → الإجراء → الاسم → المساند → الزخرفة)، RTL أصلي بخصائص منطقية دون Mirror عام، والأرقام والتواريخ والمعرفات LTR معزولة.
