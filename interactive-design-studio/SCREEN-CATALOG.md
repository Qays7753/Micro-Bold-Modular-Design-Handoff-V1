# SCREEN-CATALOG — كتالوج الشاشات

**المرجع:** `04-SCREEN-COVERAGE.csv` (بذرة 46 صفًا) + §§11، 13، 21.3. المنفذ هذه الجولة: 3 شاشات + الهيكل؛ البقية `Not Started — Deferred pending owner review` (بوابة 16).

## الشاشات المنفذة (Candidate — بانتظار مراجعة المالك)

### OVR-NOW — مشروعي الآن (Overview · مستوى 1 · تبويب مشروعي الآن)

**القرارات:** §13.2 (Question-First) · §13.4 (Snapshot Deck) · §13.19 (الأهم الآن) · §13.20 (حالات القيمة) · §21.3.
**التكوين:** عنوان داخل المحتوى + ContextTrace لآخر تحديث → Snapshot Deck (نظرة مالية/عرض الكل؛ بطاقة قوية واحدة: الكاش المتاح Indigo، ثم النتيجة/دين لك/دين عليك عبر مؤشر «n من 4») → Insight واحدة قابلة للإجراء → ملخص اليوم صفوفًا مفتوحة → آخر الحركات → تذييل مع شارة Fixtures.
**الحالات (6):**

| الحالة | ما تُظهره | مسار عميق |
|---|---|---|
| complete | وضع موثوق كامل | `#/OVR-NOW?state=complete` |
| partial | نتيجة تقديرية (تنقص تكاليف 3 منتجات) + ديون جزئية بأثر على القرار | `#/OVR-NOW?state=partial` |
| insufficient | النتيجة غير متاحة بعد (`لا يمكن حسابه`) + ديون `—` بحاجة للمراجعة | `#/OVR-NOW?state=insufficient` |
| first-use | Micro First Move: دعوة واحدة بلا أرقام مختلقة | `#/OVR-NOW?state=first-use` |
| offline | System Ribbon + قيم آخر نسخة محفوظة + عمليتان بانتظار الإرسال | `#/OVR-NOW?state=offline` |
| error | Recovery Stage داخل منطقة الملخص فقط مع بقاء بقية الشاشة | `#/OVR-NOW?state=error` |

**صدق مالي:** الكاش يحمل بيان نزاهة «الكاش ليس ربحًا — يشمل رأس المال العامل»؛ الحالة العاجلة (دين مستحق اليوم) في Insight ظاهرة لا خلف Swipe.

### OPS-SALE-CREATE — تسجيل بيع نقدي/آجل (Operations · مستوى 3 · من قسم العمل)

**القرارات:** §12 (Guided Open Forms: نموذج سريع) · §12.4 (Sheet للقوائم الطويلة) · §13.8 (Impact Preview) · §13.20 · §11.10 (مستوى ثالث: بلا شريط سفلي، «إلغاء» يمينًا).
**التكوين:** Segmented نقدي/آجل → العميل (مشروط بالآجل — يفتح Sheet بحث+قائمة) → سطور الأصناف (كمية ±، سعر، إجمالي سطر؛ منتج بسعر غير مسجل يظهر `—` لا صفرًا) → تفاصيل إضافية قابلة للطي → أثر العملية (قبل/بعد بقيم Fixtures موسومة) → شريط إجراء سفلي ثابت بزر واحد باسم النتيجة `تسجيل البيع`.
**الحالات (9):** empty · filled · validation (أخطاء محددة بعد المتابعة: عميل آجل مطلوب + سعر غير مسجل) · impact · impact-credit (دين أبو محمد 62.50 ← 90.00) · saving (Action Hold بإشارة واحدة) · failure (لم تُحفظ العملية؛ المدخلات باقية + إعادة المحاولة) · success (عودة للسياق + Echo واحد + محاكاة موسومة) · offline-save (محفوظ على هذا الهاتف + بانتظار الإرسال).
**تفاعل حي:** تبديل النمط، أوراق اختيار العميل/الصنف مع بحث، إضافة للسلة، تحقق بعد المتابعة، حفظ → Echo — مثبت باللقطات `interaction_*`.

### FIN-OVERVIEW — المالية (Finance · مستوى 1 · تبويب المالية)

**القرارات:** §13.2 (الأسئلة الخمسة) · §13.3 (عرض المبالغ) · §13.7 (الكاش والمحافظ و«بانتظار تحديد المحفظة») · §13.11 (النتيجة والاكتمال) · §13.12 (الفترة والمقارنة) · §13.20.
**التكوين:** عنوان + زر فترة واحد (قائمة من مصدرها) → **كم معي الآن؟** كتلة Indigo (الكاش + صفوف المحافظ + Seam غير موزع 5.00 د.أ بإجراء + بيان نزاهة) → **ماذا دخل وماذا خرج؟** (إيرادات/مصروفات + مقارنة مفسرة أو «لا توجد بيانات كافية للمقارنة») → **ما لي وما عليّ؟** (صفان مفصولان بلا رقم صافٍ) → **النتيجة واكتمالها** (ResultBlock) → تذييل Fixtures.
**الحالات (6):** complete · partial (تقديرية + مقارنة معطلة) · insufficient (لا يمكن حسابه + ديون `—`) · zero (مصروفات 0.00 حقيقية + ديون لك 0.00 بسطر هادئ Clear State) · negative (خسارة `−80.00` مشروحة بالنص) · offline.
**لا Chart:** النمط مشروط بسؤال منتج وبيانات مثبتة (FIN-CHARTS صف جرد مشروط) — موثق كقرار تنفيذ متعمد لا نقصًا عارضًا.
